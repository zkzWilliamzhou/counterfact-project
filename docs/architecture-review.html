Candidate 1 — deepen the replay module

Strong

Before: one shallow module

counterfact/runner.py (293 lines)

Problem: pure state transformation, filesystem copying, subprocess control and log construction shared one module. The interface was nearly as complex as the implementation, and there was no seam on which to test the search algorithm without launching processes.

Deletion test: deleting _compose would only move complexity elsewhere. Deleting the whole module would concentrate it — the signal to deepen.

Strong

After: one deep seam, two adapters

composition.py · workspace.py · process.py · ports.py · runner.py (140 lines)

Solution: a pure module computes the complete env/argv/umask triple; two adapters own the filesystem and the process; Observer in ports.py is the interface that is the test surface.

Benefits: locality — each external dependency lives in exactly one place. Leverage — one compose() serves every experiment. The ddmin and proof modules now depend on an interface, and the whole algorithm is testable without a process.
